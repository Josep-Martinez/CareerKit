# li-dm

Before presenting a connection note or DM, apply `.agents/skills/li-bilingual/SKILL.md`. Give separate Spanish and English versions and recommend sending only the version matching the recipient or conversation.

The connection note should fit LinkedIn's current limit; check the current UI
or official documentation before reporting an exact character maximum. The
first DM should make a specific, honest reason to connect clear. Neither is a
pitch.

## Before writing, get the specifics

Ask for, in one batched question:

1. **Who** - name, role, company.
2. **The hook** - the actual reason to reach out now. A post they wrote, a
   thing their company shipped, a mutual connection, a talk they gave. Not
   "they fit my ICP".
3. **What the user wants** - a conversation, a referral, a job, a sale. Be
   honest internally, even if the message does not lead with it.

If there is no specific reason to message this person today, say so. Do not
invent a connection or predict a response rate.

## The invite note

```
{one specific reference to them} + {one line of who you are} + {no ask}
```

The note asks for nothing. It exists to make the accept obvious. Count
characters only against a verified current limit, and show the count.

```
Hola [nombre], leí tu publicación sobre [tema concreto]. Mi experiencia en
[área confirmada] me llevó a interesarme por [tema relacionado]. Me interesa
seguir lo que compartes sobre [tema].
                                                          [count to verify]
```

This is a fictional structure example, not a claim about the user's experience
or a real post. Replace every bracketed item with a verified detail.

## The first message, after they accept

Send it when the context is still relevant and the user has time to reply. Do not
present a fixed wait as a platform rule.

- **Keep it concise.** Match the message to the relationship and context.
- **Reference the specific thing** from the note - continuity is the whole
  reason the note was specific.
- **Offer useful context before asking, when appropriate.** Use a detail,
  answer or resource that is relevant and verified.
- **If making an ask, keep it proportionate to the relationship.**
- Include a calendar link only when it fits the relationship and the person has
  agreed to schedule time; avoid making an unsolicited first message feel like
  a sales sequence.

## Follow-ups

Follow-ups are optional; stop when there is no new, genuine reason to write.

- A later follow-up can add something new. Avoid "just bumping this" or
  "following up on my last message" when there is no new context.
- If closing the loop is appropriate, say you will stop and mean it. Do not
  claim that this wording or a particular delay improves reply rates.

Then stop unless the user has a new, genuine reason to contact them. These timing
suggestions are optional; no message is scheduled or sent automatically.

## Never

- Draft messages only; the user sends them manually. Do not automate invitations
  or follow-ups.
- Never fabricate a mutual connection, a shared school, or having read
  something the user has not read.
- Never write the message that opens "I hope this message finds you well".
- Do not give a fixed daily invitation cap without checking current official
  guidance and the account's own limits.

## Output

The invite note with its character count, a first message, and optional
follow-ups. Include timing only if the user requests it or supplies a plan.
Review drafts with `.agents/skills/li-human/SKILL.md`; the user sends them
manually.
